Viewport
The visible area of a web page or app on a device screen. On mobile, the viewport is typically narrower than on desktop, requiring responsive design adjustments.
Safe Area
The portion of the screen guaranteed not to be obscured by device hardware (notches, rounded corners, home indicators). iOS introduced safe area layout guides; Android followed with display cutout APIs.
Notch
A cutout at the top of the display housing front-facing cameras and sensors. Popularized by iPhone X (2017) and adopted by many Android OEMs. Apps must account for notch insets.
Dynamic Island
Apple's interactive pill-shaped cutout (iPhone 14 Pro+) that expands to show real-time activities like timers, music playback, and navigation. Developers integrate via the Live Activities API.
DPI (Dots Per Inch)
A measure of pixel density on a screen. Higher DPI means sharper text and images. Common mobile DPI buckets: mdpi (160), hdpi (240), xhdpi (320), xxhdpi (480), xxxhdpi (640).
PPI (Pixels Per Inch)
The actual pixel density of a display, calculated from resolution and screen size. Often used interchangeably with DPI in mobile contexts, though DPI technically refers to print.
Retina Display
Apple's marketing term for screens with pixel density high enough (typically 326+ PPI) that individual pixels are indistinguishable at normal viewing distance. Requires @2x and @3x image assets.
Screen Density
The number of pixels within a physical area of the screen. Android categorizes density into buckets (ldpi, mdpi, hdpi, xhdpi, xxhdpi, xxxhdpi) to serve appropriately sized resources.
Resolution
The total number of pixels on a display, expressed as width x height (e.g., 1170 x 2532 for iPhone 14). Higher resolution enables sharper visuals but requires more GPU resources.
Aspect Ratio
The proportional relationship between screen width and height (e.g., 16:9, 19.5:9). Modern phones use taller ratios, requiring apps to handle varying aspect ratios gracefully.
Density-Independent Pixels (dp/dip)
An abstract unit on Android that normalizes pixel values across different screen densities. 1 dp equals 1 physical pixel at 160 DPI (mdpi). UI layouts should use dp for consistent sizing.
Points (pt)
iOS's density-independent unit. 1 point equals 1 pixel on non-Retina, 2 pixels on @2x Retina, and 3 pixels on @3x Retina displays. All iOS layout dimensions are specified in points.
Logical Pixels
A platform-agnostic term for density-independent units (dp on Android, pt on iOS, logical pixels in Flutter). They abstract away physical pixel density for consistent cross-device layouts.
Foldable Display
A screen that physically folds, enabling devices to transform between phone and tablet form factors. Requires apps to handle continuity, multi-window states, and hinge-aware layouts.
Refresh Rate
How many times per second the display updates its image, measured in Hz. Standard is 60 Hz; ProMotion (Apple) and high-refresh Android phones support 90-120 Hz for smoother animations.
Always-On Display (AOD)
A low-power mode showing essential info (time, notifications) on the lock screen without fully waking the device. Supported on OLED screens via selective pixel illumination.

Tab Bar / Bottom Navigation
A bar at the bottom of the screen with 3-5 icons representing top-level destinations. The most common mobile navigation pattern. Each tab typically maintains its own navigation stack.
Stack Navigation
A LIFO (last-in, first-out) navigation model where screens are pushed onto and popped off a stack. The back button/gesture returns to the previous screen. Foundation of mobile navigation.
Drawer / Hamburger Menu
A side panel (typically from the left) containing navigation links, revealed by tapping a three-line (hamburger) icon. Common for apps with many destinations but criticized for hiding navigation.
Deep Linking
A URL or URI that opens a specific screen or content within an app rather than the home screen. Enables sharing, marketing, and cross-app navigation. Requires URL scheme or universal link configuration.
Universal Links (iOS)
Apple's deep linking mechanism using standard HTTPS URLs. When the app is installed, tapping a universal link opens the app directly; otherwise, it falls back to the website.
App Links (Android)
Android's verified deep linking system using HTTPS URLs with Digital Asset Links verification. Provides direct app opening without disambiguation dialogs when properly configured.
Modal
A screen or dialog that overlays the current content, requiring user interaction before returning. Used for focused tasks like login, compose, or confirmations. Presented modally rather than pushed onto the stack.
Bottom Sheet
A panel that slides up from the bottom of the screen, partially or fully covering content. Used for contextual actions, details, or secondary navigation. Can be dismissible or persistent.
Gesture Navigation
System-level navigation using swipe gestures instead of on-screen buttons. iOS uses edge swipes for back and home; Android 10+ offers a fully gestural navigation mode.
Breadcrumb Navigation
A trail showing the user's path through hierarchical content (e.g., Home > Category > Item). Less common in mobile than web, but useful in content-heavy or settings screens.
Segmented Control
A horizontal bar of two or more segments that act as mutually exclusive tabs within a single screen. Used for filtering content or switching views without full navigation.
Nested Navigation
Multiple navigation stacks or navigators embedded within each other (e.g., tabs containing stacks). Common in React Navigation and SwiftUI NavigationSplitView patterns.

App Bar / Navigation Bar
The horizontal bar at the top of a screen showing the title, back button, and action items. Called UINavigationBar on iOS and TopAppBar on Android (Material Design).
Floating Action Button (FAB)
A circular button floating above content, representing the primary action on a screen. A Material Design pattern (e.g., compose in email, add in lists). Typically positioned at the bottom-right.
Scaffold
A structural layout component (Flutter/Jetpack Compose) that provides slots for app bar, body, FAB, drawer, bottom bar, and snackbar. Establishes the basic visual structure of a screen.
Pull-to-Refresh
A gesture where pulling down on scrollable content triggers a data refresh. Indicated by a spinner or animation. Implemented via UIRefreshControl (iOS) or SwipeRefreshLayout (Android).
Snackbar / Toast
Brief messages shown at the bottom (Snackbar, Material) or center (Toast, Android) of the screen. Snackbars may include an action button; toasts are purely informational and auto-dismiss.
Skeleton Screen
Placeholder shapes (gray boxes, lines) mimicking the page layout shown while content loads. Provides better perceived performance than spinners by giving users a preview of the upcoming content.
Shimmer Effect
An animated gradient sweep over skeleton placeholders, creating a "loading" visual cue. Popularized by Facebook's content loading pattern. Signals that content is actively being fetched.
Carousel / Horizontal Scroll
A horizontally scrollable set of cards or images. Used for featured content, onboarding, or galleries. Requires careful handling of paging, snapping, and accessibility.
Action Sheet
An iOS-style panel sliding up from the bottom presenting a set of actions related to the current context. Similar to a bottom sheet but specifically for action choices.
Chip
A compact UI element representing an input, attribute, or action (e.g., filter tags, contact names). Can be selectable, deletable, or actionable. Part of Material Design component library.
Badge
A small indicator (often a red circle with a number) overlaid on an icon or element to signal unread items, notifications, or status. Used on tab bar icons, app icons, and list items.
Stepper
A UI control for incrementing or decrementing a numeric value with +/- buttons. Common in e-commerce (quantity), settings (font size), and forms.
Switch / Toggle
A two-state control (on/off) used for binary settings. Provides immediate visual feedback. Called UISwitch on iOS and Switch/SwitchCompat on Android.
Date/Time Picker
A specialized input for selecting dates, times, or both. Platform-specific implementations include iOS wheel pickers and Material Design calendar/clock pickers.
Search Bar
A text input field for searching content within an app. Often includes suggestions, recent searches, and voice input. UISearchController (iOS) or SearchView (Android).

Dart Responsive layout with LayoutBuilder in Flutter 
class ResponsiveLayout extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return LayoutBuilder(
      builder: (context, constraints) {
        if (constraints.maxWidth > 900) {
          // Desktop: side-by-side
          return Row(children: [
            Expanded(flex: 1, child: Sidebar()),
            Expanded(flex: 3, child: ContentArea()),
          ]);
        } else if (constraints.maxWidth > 600) {
          // Tablet: narrower sidebar
          return Row(children: [
            SizedBox(width: 200, child: Sidebar()),
            Expanded(child: ContentArea()),
          ]);
        }
        // Phone: stacked
        return Column(children: [ContentArea()]);
      },
    );
  }
}
Responsive Design
An approach where the UI fluidly adapts to different screen sizes using flexible grids, relative units, and breakpoints. Content reflows rather than being redesigned for each screen size.
Adaptive Design
An approach that provides distinct layouts for specific screen sizes or device types rather than fluid reflow. The app detects the device class and serves the appropriate layout.
Auto Layout (iOS)
Apple's constraint-based layout system where UI elements are positioned by defining relationships (constraints) between them. Handles rotation, dynamic type, and varying screen sizes automatically.
ConstraintLayout (Android)
Android's flexible layout manager that positions child views using constraints relative to siblings or the parent. Enables flat view hierarchies and complex responsive layouts without nesting.
Flexbox
A one-dimensional layout model that distributes space among items in a container. Used in React Native and CSS. Defines how items grow, shrink, and align along a main axis and cross axis.
Grid Layout
A two-dimensional layout system that organizes elements into rows and columns. Used in CSS Grid, LazyVerticalGrid (Compose), and UICollectionView compositional layouts.
Material Design
Google's design system providing guidelines, components, and patterns for Android and cross-platform apps. Material 3 (Material You) introduces dynamic color theming and updated components.
Human Interface Guidelines (HIG)
Apple's comprehensive design guidelines for iOS, iPadOS, macOS, watchOS, and visionOS. Covers navigation, typography, iconography, accessibility, and platform-specific patterns.
Design Tokens
Named entities storing visual design attributes (colors, spacing, typography, shadows) as platform-agnostic values. Enable consistent theming across platforms and design-to-code workflows.
Dark Mode
An alternate color scheme using dark backgrounds and light text. Reduces eye strain in low light and saves battery on OLED screens. Must be supported system-wide and in-app.
Dynamic Color / Material You
Android 12+ feature that generates a personalized color palette from the user's wallpaper. Apps using Material 3 can adopt these dynamic colors for a cohesive system-wide look.
Safe Area Insets
Padding values representing areas of the screen obscured by hardware (notches, home indicators, status bars). APIs provide these insets so content remains fully visible and interactive.

UIKit
Apple's imperative, event-driven UI framework for iOS. Uses view controllers, storyboards, and Auto Layout. Mature and feature-complete, still used for complex custom interfaces.
SwiftUI
Apple's declarative UI framework (2019+). Build interfaces using Swift code with automatic state management, previews, and cross-Apple-platform support. Increasingly the default for new iOS projects.
Xcode
Apple's integrated development environment (IDE) for building apps across all Apple platforms. Includes Interface Builder, Instruments profiler, Simulator, and the Swift/Objective-C compiler toolchain.
TestFlight
Apple's beta testing platform. Distribute pre-release builds to up to 10,000 external testers. Provides crash reports, feedback, and automatic update delivery.
Keychain
iOS's secure, encrypted storage for sensitive data (passwords, tokens, certificates). Data persists across app reinstalls and can be shared between apps via Keychain Access Groups.
Core Data
Apple's object graph and persistence framework. Provides data modeling, lazy loading, undo support, and iCloud sync (via NSPersistentCloudKitContainer). More than a database—it's an object lifecycle manager.
SwiftData
Apple's modern persistence framework (2023+), replacing Core Data's complexity with Swift macros (@Model, @Query). Uses the same underlying SQLite engine with a vastly simplified API.
Combine
Apple's reactive programming framework for processing asynchronous events over time. Provides publishers, subscribers, and operators for composing event-driven data pipelines.
App Clips
Lightweight portions of an iOS app (<15 MB) that launch instantly via NFC tags, QR codes, or App Clip links. Enable quick tasks without downloading the full app.
StoreKit 2
Apple's modernized in-app purchase framework using Swift concurrency (async/await). Handles subscriptions, consumables, and non-consumables with server-side receipt verification.
WidgetKit
Framework for building Home Screen, Lock Screen, and StandBy widgets on iOS. Widgets use SwiftUI and a timeline-based refresh mechanism, not live views.
Live Activities
Real-time, glanceable UI on the Lock Screen and Dynamic Island showing ongoing events (sports scores, deliveries, timers). Updated via push notifications or ActivityKit.
Provisioning Profile
A file linking an app ID, development certificates, and device UDIDs, enabling code to run on specific devices. Required for development, ad hoc, and enterprise distribution.
Info.plist
A property list file containing app configuration metadata: bundle ID, required permissions, supported orientations, URL schemes, and more. Read by the system at install and launch time.

Kotlin Room database with DAO and ViewModel 
// Entity
@Entity(tableName = "tasks")
data class Task(
    @PrimaryKey(autoGenerate = true) val id: Int = 0,
    val title: String,
    val isComplete: Boolean = false
)

// DAO
@Dao
interface TaskDao {
    @Query("SELECT * FROM tasks ORDER BY id DESC")
    fun getAll(): Flow<List<Task>>

    @Insert
    suspend fun insert(task: Task)
}

// ViewModel
@HiltViewModel
class TaskViewModel @Inject constructor(
    private val dao: TaskDao
) : ViewModel() {
    val tasks = dao.getAll()
        .stateIn(viewModelScope, SharingStarted.Lazily, emptyList())

    fun addTask(title: String) = viewModelScope.launch {
        dao.insert(Task(title = title))
    }
}
Activity
A single, focused screen in an Android app. Activities manage their own lifecycle (created, started, resumed, paused, stopped, destroyed) and serve as entry points for user interaction.
Fragment
A reusable UI component within an Activity, with its own lifecycle. Fragments enable modular screen design, multi-pane layouts, and navigation component integration.
Jetpack Compose
Android's modern declarative UI toolkit built in Kotlin. Replaces XML layouts with composable functions, offering reactive state management, theming, and animation with less boilerplate.
Room Database
A Jetpack persistence library providing an abstraction layer over SQLite. Uses annotations (@Entity, @Dao, @Database) to generate boilerplate code for type-safe database access.
ViewModel
A Jetpack architecture component that stores and manages UI-related data, surviving configuration changes (e.g., screen rotation). Scoped to an Activity or Fragment lifecycle.
Intent
A messaging object for requesting an action from another component. Explicit intents target specific components; implicit intents declare an action and let the system find suitable handlers.
Broadcast Receiver
A component that listens for and responds to system-wide broadcast announcements (battery low, network change, boot completed). Can be registered in the manifest or dynamically at runtime.
Content Provider
A component that manages shared app data (contacts, media, files) via a structured interface. Other apps access data through ContentResolver using URIs, enabling secure data sharing.
Service
A component that performs long-running operations in the background without a UI. Foreground services show a notification; WorkManager is preferred for deferrable background tasks.
WorkManager
A Jetpack library for scheduling deferrable, guaranteed background work (sync, uploads, cleanup). Respects system constraints (network, battery) and survives app restarts and device reboots.
Gradle
Android's build automation tool. Manages dependencies, build variants (debug/release), product flavors, code signing, and the entire compilation pipeline via build.gradle(.kts) scripts.
AndroidManifest.xml
The app's declaration file specifying package name, components (activities, services, receivers), permissions, hardware requirements, and minimum SDK version. Required for every Android app.
Hilt
A dependency injection library built on top of Dagger, designed specifically for Android. Provides standard component scopes (Activity, Fragment, ViewModel) with annotation-based configuration.
Jetpack Navigation
A framework for implementing navigation across fragments, activities, and composables. Uses a navigation graph (XML or Kotlin DSL) with built-in support for deep links and safe args.

Swift ScenePhase lifecycle handling in SwiftUI 
@main
struct MyApp: App {
    @Environment(.scenePhase) private var scenePhase

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
        .onChange(of: scenePhase) { oldPhase, newPhase in
            switch newPhase {
            case .active:
                print("App is active — resume tasks")
            case .inactive:
                print("App inactive — pause timers")
            case .background:
                print("App backgrounded — save state")
                saveAppState()
            @unknown default:
                break
            }
        }
    }

    private func saveAppState() {
        UserDefaults.standard.set(Date(), forKey: "lastBackground")
    }
}
Cold Start
Launching an app from scratch when it's not in memory. The slowest startup type: the system creates the process, initializes the runtime, and loads the app. Optimize by deferring non-essential work.
Warm Start
Relaunching an app whose process is still in memory but the activity/UI was destroyed. Faster than cold start since the process and some objects are already initialized.
Hot Start
Bringing a backgrounded app to the foreground. The fastest resume—the app's activity is still in memory and only needs to redraw. No initialization or data reloading required.
Foreground
The app state where the app is visible, interactive, and receiving user input. The app has the highest priority for system resources when in the foreground.
Background
The app state where the app is not visible but may still execute limited tasks (audio playback, location tracking, data sync). Heavily restricted on both iOS and Android to preserve battery.
Suspended
An iOS app state where the app is in memory but not executing code. The system may terminate suspended apps without notice to reclaim memory. No background execution occurs in this state.
App Not Running
The state before any launch or after the system/user terminates the app. No process exists in memory. Next launch will be a cold start.
State Restoration
The process of saving and restoring an app's UI state across termination and relaunch. Ensures users return to exactly where they left off, even if the system killed the app.
Process Death
When the OS terminates an app's process (usually while backgrounded) to reclaim memory. Apps must save critical state to persist through process death and restore it on relaunch.
Lifecycle Observer
An API for monitoring app/component lifecycle events. Android offers ProcessLifecycleOwner (app-level) and LifecycleObserver (component-level); iOS uses UIApplicationDelegate and SceneDelegate methods.
Scene Delegate (iOS)
An iOS 13+ API for managing app UI lifecycle per window/scene. Supports multi-window on iPad and handles scene connection, disconnection, foreground, and background transitions.
Background Modes

REST API
An architectural style using HTTP methods (GET, POST, PUT, DELETE) on resource URLs. The most common API pattern for mobile apps. Stateless, cacheable, and well-tooled across platforms.
GraphQL
A query language for APIs where clients request exactly the data they need. Reduces over-fetching and under-fetching common with REST. Single endpoint serves all queries.
WebSocket
A protocol providing full-duplex communication over a single TCP connection. Enables real-time features like chat, live updates, and multiplayer. Lower overhead than HTTP polling.
gRPC
A high-performance RPC framework using Protocol Buffers for serialization. Supports streaming, strongly-typed contracts, and efficient binary encoding. Used in backend-to-backend and mobile-to-backend communication.
SSL/TLS
Cryptographic protocols securing data in transit between client and server. All modern mobile APIs require HTTPS. TLS 1.3 is the current standard with faster handshakes.
Certificate Pinning
A security technique that restricts which certificates the app trusts for a specific server. Prevents man-in-the-middle attacks even if a CA is compromised. Can be hash-based or certificate-based.
Offline-First
An architecture where the app stores data locally and syncs with the server when connectivity is available. Ensures full functionality without network access. Requires conflict resolution strategies.
Caching Strategy
Techniques for storing API responses locally to reduce network requests and improve performance. Common strategies: cache-first, network-first, stale-while-revalidate, and cache-then-network.
Retry Logic / Exponential Backoff
Automatically retrying failed network requests with increasing delays (1s, 2s, 4s, 8s...) and optional jitter. Prevents overwhelming servers during outages and handles transient failures gracefully.
Server-Sent Events (SSE)

export function TaskList() {
  const [tasks, setTasks] = useState(initialTasks);

  // Stable reference — won't cause child re-renders
  const handleToggle = useCallback((id) => {
    setTasks(prev =>
      prev.map(t => t.id === id ? { ...t, done: !t.done } : t)
    );
  }, []);

  return (
    <FlatList
      data={tasks}
      keyExtractor={t => t.id}
      renderItem={({ item }) => (
        <TaskRow task={item} onToggle={handleToggle} />
      )}
    />
  );
}

        let request = VNCoreMLRequest(model: vnModel) { req, err in
            if let err { cont.resume(throwing: err); return }
            guard let results = req.results as? [VNClassificationObservation],
                  let top = results.first else {
                cont.resume(returning: "Unknown")
                return
            }
            cont.resume(returning: "\(top.identifier) (\(Int(top.confidence * 100))%)")
        }
        let handler = VNImageRequestHandler(cgImage: image)
        try? handler.perform([request])
    }
}
On-Device AI / Core ML
Running machine learning models directly on the device for real-time inference without network roundtrips. Apple's Core ML, Google's ML Kit, and TensorFlow Lite enable vision, NLP, and speech processing locally.
Kotlin Multiplatform Expansion
KMP maturing beyond shared business logic to include shared UI experiments (Compose Multiplatform). Major companies (Netflix, VMware, Philips) adopting KMP for iOS/Android code sharing in production.
Material 3 Expressive
Google's evolution of Material Design emphasizing personalization, fluid motion, and expressive components. Introduced in 2025, bringing more customizable shape, color, and animation systems.
visionOS / Spatial Computing
Apple's platform for Vision Pro headset, enabling spatial apps that blend with the user's environment. Uses SwiftUI, RealityKit, and ARKit for immersive, volumetric experiences.
Declarative UI Convergence
The industry-wide shift toward declarative UI patterns: SwiftUI (Apple), Jetpack Compose (Android), Flutter (Dart), React Native. Imperative frameworks (UIKit, Android Views) are in maintenance mode.
Edge Computing for Mobile
Processing data closer to the user (edge servers, CDN compute) to reduce latency for mobile apps. Enables real-time AI inference, game streaming, and AR experiences without distant cloud roundtrips.
Super Apps
A single app platform integrating multiple services (messaging, payments, shopping, transport). Prominent in Asia (WeChat, Grab, Gojek). Built using mini-app architectures within a host app.
Privacy-First Architecture
Designing apps with privacy as a core principle. Includes on-device processing, differential privacy, minimal data collection, App Tracking Transparency (ATT), and privacy nutrition labels.
Passkeys
A passwordless authentication standard using WebAuthn/FIDO2. Cryptographic key pairs replace passwords, synced via iCloud Keychain or Google Password Manager. Phishing-resistant and cross-platform.
App Intents / Shortcuts
Frameworks for exposing app functionality to Siri, Shortcuts, Spotlight, and the Action Button. Apple's App Intents framework (2022+) simplifies integration with system intelligence features.
Progressive Web App (PWA)
Web applications providing app-like experiences: offline support, push notifications, home screen install. Built with web technologies (HTML, CSS, JS) and service workers. An alternative to native for certain use cases.
Micro-Frontends for Mobile
An architectural pattern where different teams own independent, deployable feature modules within a single app. Enables parallel development and independent release cycles in large organizations.

ASO (App Store Optimization)
Optimizing app store listings (title, keywords, description, screenshots, ratings) to improve search ranking and conversion rate. The mobile equivalent of SEO for app discoverability.
Feature Flags
Boolean or multivariate toggles controlling feature availability without deploying new code. Enable gradual rollouts, A/B tests, and instant kill switches. Tools: LaunchDarkly, Firebase Remote Config, Unleash.
Remote Config
Server-controlled key-value pairs that change app behavior without an update. Used for feature flags, UI text, thresholds, and emergency toggles. Firebase Remote Config is the most popular solution.
Phased Rollout
Gradually releasing an app update to increasing percentages of users (1% > 5% > 20% > 50% > 100%). Both App Store and Google Play support phased releases to catch issues before full rollout.
Canary Release
Deploying a new version to a small subset of users first to detect issues before wider release. Named after canaries in coal mines. Combined with monitoring to auto-halt on anomaly detection.
Blue-Green Deployment
Maintaining two identical environments (blue = current, green = new). Traffic switches from blue to green once validated. In mobile, this concept applies to backend APIs serving mobile clients.
Crash Reporting
Automated collection of crash data (stack traces, device info, user actions) when the app terminates unexpectedly. Essential for prioritizing bugs. Tools: Crashlytics, Sentry, Bugsnag, Datadog.
App Review Guidelines
Rules set by Apple and Google that apps must comply with for store acceptance. Cover content, privacy, security, performance, design, and business model requirements. Rejection requires addressing cited violations.
Push Notification Service
Platform infrastructure for delivering messages to devices: APNs (Apple Push Notification Service) for iOS and FCM (Firebase Cloud Messaging) for Android. Requires server-side integration and device token management.
Deep Link Routing
Server-side or in-app logic that maps incoming deep link URLs to specific screens or actions. Libraries like Branch.io and Firebase Dynamic Links handle deferred deep links (working even through app install).
Mobile DevOps
The practice of applying DevOps principles (automation, CI/CD, monitoring, collaboration) specifically to mobile app development. Addresses unique mobile challenges: code signing, device fragmentation, store reviews.
Backend-Driven UI
An architecture where the server sends UI component definitions (layout, content, actions) that the app renders dynamically. Enables UI updates without app releases. Used by Airbnb, Lyft, and server-driven rendering frameworks.
